# 齐司礼 AI · 跨世界连接版

> 一个**轻量级、纯前端、可在浏览器直接打开**的角色 AI 聊天应用。
> 基于 DeepSeek API，数据全部存本地，不依赖任何后端服务。
>
> ⭐ **本作品集中最完整、最能体现 AI 协作开发能力的项目**，强烈建议重点查看。

[🔗 在线体验](#本地运行) ｜ [📖 详细使用说明](./使用说明.md) ｜ [🎯 Prompt 设计文档](./prompt.md)

## ✨ 项目亮点

- 🎭 **5 模块独立可调教的 Prompt 系统**：把"齐司礼"这个角色拆成 5 个独立模块（世界背景/人设/对话规则/记忆/关系），每个模块单独维护，调教不影响其他模块
- 🧠 **三层记忆系统**：短期对话记忆 + 用户画像记忆 + 关键事件记忆，让角色能"记住"与用户的过往
- 🌐 **跨世界连接机制**：不是"角色皮肤聊天"，而是让角色以"跨世界重新建立联系"的方式与用户互动
- 📱 **移动端优先**：在 iPhone Koder App 或任意浏览器直接运行
- 🔐 **数据本地化**：所有对话、设置、记忆都存在 localStorage，不上服务器
- 🎨 **精致 UI**：浅青/雾白/淡金配色，参考原游戏角色视觉

## 🤖 AI 协作开发流程（重点）

这个项目是**用 AI 工具（Claude / Codex 类）指挥 AI 写代码**的典型案例。以下是真实的协作过程复盘：

### 阶段 1：需求拆解与架构设计

**我**先把需求拆成几个明确的子任务：
1. 角色人设的核心矛盾点是什么（嘴硬心软设计师）
2. Prompt 怎么拆模块才能"可调教"
3. 记忆系统怎么设计才不会让 AI 跑偏
4. UI 在移动端怎么布局

> 💡 **经验**：让 AI 写代码之前，必须先把"产品逻辑"想清楚。否则 AI 会基于自己的默认理解瞎写，写完才发现不符合预期。

### 阶段 2：Prompt 模块化设计

我让 AI 设计 Prompt 结构，给的关键约束：
- **不要**写成"角色介绍卡"（一堆设定堆一起）
- **要**按"行为系统"设计（每个模块解决一个具体行为问题）
- 每个模块独立成文件，便于后续单独调整

**AI 第一版输出**：把整个 prompt 写成一个超长字符串。
**我的反馈**：不对，按模块拆成 5 个独立 JS 文件。
**AI 第二版**：拆开了，但各模块之间有重复内容。
**我的反馈**：模块之间去重，每个模块聚焦一个维度。
**最终版**：5 个模块 + 一个装配器（prompt.js），每个模块 30-200 行，互不重复。

### 阶段 3：核心对话逻辑迭代

**我**给的约束：
- AI 回复要像真人微信聊天（短句、留白、不油腻）
- 不能突破"傲娇但深情"的底线
- 不能解释"我是 AI 所以……"
- 一次回复 1-3 句话，最多 5 句

**AI 翻车案例 1**：写出了"作为你的 AI 男友……"的开头。
**我的反馈**：明确禁止打破第四面墙，并在 prompt 里加 ❌ 标记。
**AI 翻车案例 2**：回复过长，抒情式长段落。
**我的反馈**：在 prompt 里加"反例对照表"，让 AI 知道"什么是好的、什么是坏的"。
**最终**：4-5 轮迭代后基本稳定，但仍需在 prompt.js 里加"输出长度兜底截断"作为最后保险。

### 阶段 4：记忆系统设计

**我**的核心要求：
- 用户填的"关于她"信息必须能影响 AI 回复
- 但不能让 AI 在回复里直接复述这些信息（破坏沉浸感）

**AI 方案**：把用户画像拼到 system prompt 里。
**我的反馈**：会让 AI 变成"念档案"，不够真人。
**最终方案**：把记忆分为三层（短期对话 / 用户画像 / 关键事件），按"时机"注入：
- 用户画像：每次都注入（隐性影响）
- 短期对话：最近 N 轮（显式上下文）
- 关键事件：触发条件注入（比如用户提到某关键词才注入相关事件）

### 阶段 5：UI 与交互打磨

**我**的策略：
- 先让 AI 出一个"够丑但能用"的版本
- 再让 AI 优化配色、间距、动效
- 移动端适配单独迭代（用 iPhone Koder 实际测试）

**反复调整的点**：
- 输入框在底部固定 + 软键盘适配
- 打字机效果的速度（45ms/字，太快显得 AI 不够"人"，太慢用户没耐心）
- 消息气泡的圆角和阴影
- 设置面板的浮层遮罩

### 阶段 6：测试与边界 case

**我**自己当测试员，记录 AI 翻车的真实案例：
- 用户说"我喜欢你" → AI 不应直接回应"我也喜欢你"
- 用户说脏话 → AI 应保持清冷人设不破防
- 用户问"你是 AI 吗" → AI 应巧妙岔开
- 长时间对话后 AI 开始"忘记"前文 → 调整记忆注入策略

每个翻车案例都会让 AI 重新生成 prompt 对应模块，再回归测试。

## 🎓 这个项目教会我的事

1. **AI 不是写一次就完**：Prompt 工程是"调教"，不是"写完"
2. **模块化设计让调教可控**：5 个独立模块可以单独优化，不用动其他部分
3. **反例比正例更有用**：告诉 AI"不要做什么"往往比"要做什么"更有效
4. **AI 输出必须有兜底机制**：哪怕 prompt 写得再好，也要代码层加防护（比如长度截断、关键词过滤）
5. **真实测试驱动 prompt 优化**：不要空想 prompt 要怎么写，而是先让 AI 跑，收集翻车案例，反推 prompt 哪里要改

## 🔒 Security / 隐私说明

本项目所有数据（对话、API Key、记忆）都存在浏览器 `localStorage`，**不上传任何服务器**。

**一键清空（推荐）**：
1. 打开应用 → 右上角 ⚙️ 设置
2. 滚到底部，点击 **"🗑 重置全部数据（含 API Key）"**
3. 双重确认后，所有对话 / API Key / 记忆都会被彻底清空

**手动清空（开发者用）**：
浏览器 DevTools Console 执行：
```javascript
['qisili_chats_v3', 'qisili_settings_v3', 'qisili_memory_v4'].forEach(k => localStorage.removeItem(k));
location.reload();
```

> ⚠️ **重要**：本项目**不会**以任何形式把你的 API Key 上传到 GitHub 或任何服务器。代码里只有 placeholder（如 `your-api-key-here`），真实 Key 只在你自己浏览器里输入和存储。
>
> 本仓库**不包含**任何真实 API Key、聊天记录或用户数据。
